## 二、本地运行页面

需要 Node 18+。

```bash
cd app
npm install
npm run dev        # 打开 http://localhost:5173/?mode=demo
```

- `?mode=demo`：演示模式，顶部有黄色斜纹提示“模拟数据”，不连钱包、不发交易。
- 不带参数：读取 `app/public/config.json`。`miner` 为空时页面显示“未配置”，所有交易按钮禁用，**不会回退成模拟数字**。
- 管理后台入口只在连接的钱包是合约 owner 时出现；演示模式下用 `?mode=demo&admin=1` 查看。
- 正式打包：`npm run build`，把 `app/dist` 整个目录放到任意静态网站即可。手机用户在钱包 App（TokenPocket、MetaMask、币安钱包等）的内置浏览器里打开。

## 五、奖励怎么算（结算方案）

用大白话说：

1. **估值**：Keeper 大约每 10 分钟调用一次 `checkpoint()`（任何人都能调用）。合约用池子过去 30 分钟的时间加权价格，算出“每单位流动性值多少 USDT”。因为所有人都是同一个池子的全区间仓位，你的价值 = 你的流动性 × 这个单价。
2. **两次检查之间**：按上一次检查的估值计息。
3. **检查点生效**：每次检查立即生效；先把到此刻为止的奖励按旧估值记完，再用新估值。
4. **服务离线**：最后一次有效估值超过 2 小时，自动停止计息；恢复后从恢复那一刻开始，不补计。用户入金、领取也会顺带触发检查。
5. **暂停**：储备或授权不够、价格不可用、管理员暂停时，停止新入金和新计息；已记的奖励保留；退出本金不受任何影响（退出时不读价格、不看储备）。
6. **储备够不够**：可用额度 = min(运营钱包余额, 授权额度)，按喜羊羊时间加权价折成 USDT，要覆盖“已累计未支付”+“3 天的发放量”。不是余额大于 0 就行。
7. **推荐奖励**：下级每次结算（他自己操作，或 Keeper 每小时批量结算）时，把这段时间的 10%/5% 记给“上一次结算时确定的两个有效上级”。如果某个上级在这段时间内自己退出导致不满足 100 USDT，从他退出那一刻截止。然后重新沿推荐链向上找新的两个有效上级，用于下一段。已经记给谁的奖励不会因为后来的变化被改写。
8. **领取**：按领取那一刻的喜羊羊时间加权价，把 USDT 计价额度换算成喜羊羊，从运营钱包直接转给用户（转账扣税会整笔回滚，不会悄悄少发）。

**这是离散近似，有两点和“连续精确”不同**（需要你确认是否接受，见第九节）：
- 价格变化导致某人跌破/回到 100 USDT 时，最晚要等到他下级的下一次结算（约 1 小时内）才生效；
- 储备被撤销后，最多有一个检查间隔（约 10 分钟）还会继续计息。

计算量：每次结算最多向上查 10 层（固定上限，超出部分不分配），领取、退出都不会因为推荐链太长而无法执行。Keeper 没有任何特权，不能改余额、不能报价格、不能动本金。

## 六、管理员操作

管理员 = 运营钱包（合约 owner）。在页面“管理”里，或用区块浏览器：

- **授权 / 补充授权**：运营钱包对喜羊羊代币执行 `approve(挖矿合约, 数量)`。这是设置新额度（不是累加），请填有限额度。
- **补充储备**：把喜羊羊转入运营钱包地址即可，不需要转进合约。
- **暂停**：`setAdminPaused(true)`，只停新入金和新计息，用户随时能退出。
- **恢复**：`setAdminPaused(false)`，合约会当场检查估值、喜羊羊报价、储备；有任何一项不满足就保持暂停。
- **立即检查**：`checkpoint()`。
- 合约**没有**任何提走本金、提走仓位 NFT、拿走手续费、修改用户奖励、升级合约的功能。

## 七、部署与部署后核验（等你决定）

```bash
cp .env.example .env    # 填 RPC 和地址；私钥不要写进文件
cd contracts
source ../.env
forge script script/Deploy.s.sol --rpc-url $RPC_URL --broadcast --ledger   # 或 --account / 交互输入
```

部署后：
1. `MINER=<新地址> REWARD_POOL=... node scripts/verify-chain.mjs` 全部 PASS；
2. 在浏览器验证合约源码；
3. 运营钱包授权一个有限额度；
4. 运行 `checkpoint()`，确认 `accruing()==true`；
5. 把 `miner`、`deployBlock` 填进 `app/public/config.json`；
6. 启动 Keeper：`node scripts/keeper.mjs`（用一个只放少量 BNB 的新钱包）；
7. 先用小额走一遍：入金 → 等待 → 领取 → 部分退出 → 全部退出。

## 八、生产上线阻塞项

1. BSC 分叉测试未运行（需要 BSC 节点）。
2. 喜羊羊价格池 0xc069…5bAC 需要在部署页核验：必须是 PancakeSwap V3 池、配 USDT 或 POP、有足够价格历史和流动性。
3. 地址和代币行为（扣税、黑名单、暂停、增发、代理可升级）待 `verify-chain.mjs` + 分叉测试确认。
4. 时间加权价不是万能的：池子流动性很小时仍可能被人花钱操纵，需要你设定合理的最小流动性门槛（`MIN_POOL_LIQUIDITY` 等）。
5. 记录页目前直接按区块分段查询链上事件，公共节点查询慢、有范围限制；用户量大时需要一个事件索引服务。
6. 钱包连接只支持钱包 App 内置浏览器（注入式钱包），没有 WalletConnect 扫码连接（这次环境装不了相关库）。
7. 需要独立安全审计。
8. 合规：固定比例收益宣传和两级推荐奖励在不少地区受监管（中国大陆禁止虚拟货币相关业务），上线前请咨询当地法律意见。

## 九、需要你确认的问题

3. 第五节的两点近似（资格变化最多延迟约 1 小时生效；撤销授权后最多多计约 10 分钟）——可以吗？
4. 储备要求覆盖“未支付 + 3 天发放量”——3 天合适吗？（可在 1–30 天之间调整）

## 十、技术取舍说明

- **每人一个 V3 仓位 NFT**：最简单、隔离最清楚，手续费天然只属于本人；重复入金直接加到同一个仓位，没有多仓位循环。
- **ethers 而不是 wagmi/viem**：这次环境无法从 npm 安装 wagmi/viem，ethers v6 以单文件形式内置（MIT）。
- **许可证**：合约用到 Uniswap 的数学库（GPL-2.0-or-later），所以合约以 GPL-2.0-or-later 发布。
